Step-by-Step Tutorial

2026-11-10

Overview

scads (Single-Cell ATAC-seq Disease Scoring) computes per-cell disease relevance scores by combining single-cell chromatin accessibility data with GWAS summary statistics. The pipeline has four main steps:

Step What it does Typical runtime Peak memory
1. fastTopics Fits a topic model on the count matrix, identifies topic-specific peaks via differential expression, and computes a GC-content baseline correction. ~1 min (500 cells, 13K peaks, 5 topics) ~650 MB
2. Topic annotations Converts significant peaks per topic into BED files for S-LDSC. < 10 sec Negligible
3. S-LDSC Runs stratified LD score regression for each topic using the baseline LD v2.2 model. This is the most time-consuming step. ~8 min/topic (chr10 demo); ~1–2 hours/topic (all 22 chr) ~300 MB per topic (Python)
4. Cell scores Combines S-LDSC enrichment estimates with cell-level topic loadings to produce a per-cell disease score. < 10 sec ~650 MB

Prerequisites: Make sure you have completed all setup steps (polyFUN, LDSC, conda environment, S-LDSC reference data) described in the Getting Started guide before proceeding.

Running the pipeline step by step

While scads() can run the entire pipeline in one call, this tutorial walks through each step individually to show intermediate results. The scads() wrapper calls these same functions internally and supports checkpointing via save_intermediates = TRUE and resume_from_step.

Note: This tutorial runs on chromosome 10 only (chrs = 10) to keep runtime short (~50 min total). For a real analysis, use chrs = 1:22.

Step 1: Fit topic model with fastTopics

What this step does:

  1. Transposes the count matrix (peaks x cells -> cells x peaks) for fastTopics.
  2. Fits a Poisson NMF topic model with k topics using fastTopics::fit_topic_model().
  3. Computes a GC-content baseline correction for each topic (if baseline_method = "gc").
  4. Runs differential accessibility analysis to identify topic-specific peaks.
  5. Applies FDR correction and binarizes peak assignments.

Runtime: ~1 min for the demo dataset (500 cells, 12,971 peaks, 5 topics). Memory: ~650 MB peak.

Key parameters:

count_matrix <- demo_count_matrix
n_topics     <- 5       # number of topics to fit
n_sims       <- 1000    # Monte Carlo samples for DE analysis
n_cores      <- 8       # cores for fastTopics (Step 1 only)
bl_method    <- "gc"    # GC-content baseline correction (recommended)
bl_ct        <- NULL    # cell type for "estimate" baseline (not used here)
bl_peaks     <- NULL    # cell type peaks for "estimate" baseline (not used here)

n_s (number of simulations): Controls the number of Monte Carlo samples for differential accessibility testing. In practice, n_s = 1000 is sufficient to obtain reasonable results and is the default used in this tutorial. In the paper, we used n_s = 5000 for the final analyses. Increasing n_s improves the precision of the DE p-values but increases Step 1 runtime proportionally.

lfc.method (DE uncertainty method): Controls how per-peak, per-topic log-fold-change uncertainty is quantified in the DE step, which is the runtime bottleneck of Step 1.

Method Description
"mcmc" (Default) Random-walk MCMC (n_s samples per peak) drawing the log-rate posterior. Robust across the full count range, including the low-count / rare-peak regime where the posterior is skewed. This is what the paper used.
"laplace" A deterministic Laplace / Fisher-information approximation of the same posterior (no Monte Carlo). One crossprod and a small k x k solve per peak instead of an n_s-step chain.

When is "laplace" appropriate? It replaces the slow MCMC with a closed-form Gaussian approximation of the log-rate posterior. That approximation is accurate when the effective per-topic count at a peak, n_eff = F[peak, topic] * sum_i s_i L[i, topic], is large enough for the posterior to be approximately symmetric. Benchmarks against n_s = 1000 MCMC:

  • Recommended when the number of topics is small-to-moderate (k <= ~15) at typical read depth (>= ~10,000 reads/cell): the binarized topic annotations are 89-99% concordant with MCMC (Jaccard 0.89-0.99), while Step 1 runs ~10-45x faster (e.g. a 3+ hour DE step finishes in ~8 minutes on a 452,000-peak, k=25 dataset).
  • Use with care at high k (>= ~25) or low read depth: expect ~84% annotation concordance, with the disagreement concentrated on borderline-significant peaks (n_eff ~ 20-100). Prefer the default "mcmc" if those marginal calls are important for your analysis.

The number of topics matters more than read depth: at k = 5, thinning to ~2,000 reads/cell still gave 91% concordance. We keep "mcmc" as the default; "laplace" is an opt-in speed-up.

baseline_method: Controls how the null hypothesis is set for differential accessibility testing:

Method Description
"gc" (Recommended) Fits a GC-content-dependent baseline using an EM algorithm with a Poisson mixture model. Accounts for GC bias in chromatin accessibility.
"constant" Uses a fixed small constant (1e-7) as baseline. Simple but does not account for GC bias.
"average" Computes a genome-wide average accessibility rate.
"estimate" Estimates background from a reference cell type’s non-overlapping peaks. Requires bl_celltype and bl_celltype_peak_file.

Step 2: Generate topic annotation BED files

What this step does:

Converts the binary peak-topic assignments (Pmat) into BED files for each topic. Each BED file contains the genomic coordinates of peaks assigned to that topic, which S-LDSC uses as a custom annotation.

Runtime: < 10 seconds. Memory: Negligible.

t2_start <- Sys.time()
beddir_list <- get_annot_beds(topics_res = out1, output_dir = output_dir)
t2_end <- Sys.time()
cat("Step 2 runtime:", round(difftime(t2_end, t2_start, units = "secs"), 1), "seconds\n")

Step 3: Run S-LDSC per topic

What this step does:

For each topic annotation, this step runs the full S-LDSC pipeline:

  1. Munge summary statistics – converts GWAS sumstats to the format expected by LDSC (parquet file via munge_polyfun_sumstats.py).
  2. Create annotation – for each chromosome, marks which 1000G SNPs fall within topic peaks (via make_annot.py).
  3. Compute LD scores – calculates LD scores for the custom annotation (via ldsc.py --l2).
  4. Heritability estimation – runs partitioned heritability analysis combining the custom annotation with the baseline LD v2.2 model (via ldsc.py --h2).

The key output is the enrichment estimate per topic: how much heritability is concentrated in the topic’s peaks relative to their size.

Runtime: ~1–2 hours per topic for all 22 chromosomes. With 5 topics on chr10 only (as in this demo), expect ~50 min total running sequentially. Memory: ~300 MB per topic (Python processes).

Key parameters:

sumstats_d   <- dirname(data_file)
gwas_n       <- 45087   # GWAS sample size
trait         <- "SIM"
cont_topics  <- FALSE   # use binary (not continuous) topic annotations

n_cores_ldsc: When using the scads() wrapper, the n_cores_ldsc parameter controls how many topics run S-LDSC in parallel. By default (NULL), it uses min(detectCores(), nTopics, 5). Set n_cores_ldsc = 1 to run topics sequentially, which avoids CPU contention and is generally faster on machines with limited cores. This is separate from n_c, which controls parallelism for the fastTopics step only. In this tutorial, topics are run sequentially in a for-loop.

Step 4: Calculate cell scores

What this step does:

Combines the S-LDSC enrichment estimates with cell-level topic loadings to produce a per-cell disease relevance score:

  1. Reads the S-LDSC enrichment estimate of each topic; the estimates are used without shrinkage. Topics whose annotation is too small for S-LDSC’s p-values to control type I error are flagged: following Tashman et al. (2021), a topic must overlap at least 1.7% of the genome’s 0.01 cM blocks (min_pct_blocks), which reflects both its size and how clustered it is. Flagged topics are reported in a warning and floored to an enrichment of 1 (small_annot = "floor", the default) or kept (small_annot = "warn"). This replaces the earlier rule of 0.5% of SNPs.
  2. Computes a weighted score per cell: cs_i = sum(L_ik * a_k * e_k) / sum(L_ik * a_k), where L_ik is the cell’s loading on topic k, a_k is the number of peaks in topic k, and e_k is the S-LDSC enrichment estimate.
  3. Computes z-scores and p-values from the covariance of the enrichment estimates. By default this is the block-jackknife covariance rebuilt from S-LDSC’s delete values (ldsc_jackknife_cov()), which needs the baseline and frequency file prefixes used for S-LDSC (baseline_prefix, frq_prefix); chrs must match the chromosomes S-LDSC was run on.
  4. Estimates how reliable the ranking of the significant cells is: the resolvable-error rank FDR (rank_fdr). Calling the top k significant cells, a call counts as an error only if the cell is below the cut-off by more than one SD of the estimation noise of its score difference with the cells at the cut-off.

Runtime: < 10 seconds. Memory: ~650 MB (due to correlation matrix computation).

Understanding the output:

  • cs: The per-cell disease score. Higher values indicate greater disease relevance based on the cell’s chromatin accessibility profile.
  • z_cell: Z-score for each cell, accounting for variance in enrichment estimates and correlation between topic annotations.
  • p_cell: Two-sided p-value for each cell’s score.
  • ldsc_res_table: Raw S-LDSC results per topic. The score uses these enrichments directly, without shrinkage.
  • rank_fdr: Resolvable-error rank FDR of the significant cells (one-sided BH < 0.05). curve gives the estimated FDR when calling the top 1-50% of significant cells by score; fdr_top10 and mean_fdr summarise it. A called cell counts as an error only if it is below the cut-off by more than one SD of the estimation noise of its score difference with the cells at the cut-off, so near-ties the data cannot resolve are not counted. The FDR is usually highest for the very top cells and falls as more cells are called (see ?rank_fdr).
  • cs_dat: Intermediate values (M_i, N_i, the cell topic weights W, the floored-topic indicator drop) used in score computation.
  • topic_qc: One row per topic: S-LDSC enrichment, Prop._SNPs, the percentage of 0.01 cM blocks overlapped (pct_blocks), and whether the topic is below the size threshold (small), has negative enrichment (negative) or was floored (floored).

Higher cell scores indicate cells whose chromatin accessibility profiles overlap more strongly with disease-associated regions. Cells dominated by topics with high enrichment will receive higher scores.

Interpreting enrichment: Enrichment > 1 means heritability is concentrated in a topic’s peaks more than expected by chance. Topics with enrichment significantly > 1 (confidence interval not crossing 1) indicate disease-relevant chromatin programs. These estimates, without shrinkage, weight the cell scores in Step 4.

Z-score distribution

The z-scores account for variance in enrichment estimates and correlation between topic annotations. Under the null (no disease signal), z-scores should be approximately standard normal.

z_df <- data.frame(z = as.numeric(cs_res$z_cell))

UMAP visualization

UMAP provides a 2D embedding of cells based on the topic loading matrix (Lmat). Coloring cells by their disease score reveals whether disease-relevant cells cluster together.

if (!requireNamespace("uwot", quietly = TRUE)) {
  message("Install 'uwot' for UMAP: install.packages('uwot')")
} else {
  library(patchwork)

  # Compute UMAP from topic loadings
  set.seed(42)
  umap_coords <- uwot::umap(out1$Lmat, n_neighbors = 350, min_dist = 0.8)

  umap_df <- data.frame(
    UMAP1 = umap_coords[, 1],
    UMAP2 = umap_coords[, 2],
    cell_score = cs_res$cs,
    z_score = as.numeric(cs_res$z_cell)
  )

  # Color by dominant topic
  dominant_topic <- paste0("k", apply(out1$Lmat, 1, which.max))
  umap_df$topic <- dominant_topic

  p3 <- ggplot(umap_df, aes(x = UMAP1, y = UMAP2, color = topic)) +
    geom_point(size = 0.8, alpha = 0.7) +
    labs(title = "Dominant topic", color = "Topic") +
    theme_minimal() + theme(legend.position = "bottom")

  # Color by cell score
  p1 <- ggplot(umap_df, aes(x = UMAP1, y = UMAP2, color = cell_score)) +
    geom_point(size = 0.8, alpha = 0.7) +
    scale_color_viridis_c(option = "C") +
    labs(title = "Cell score", color = "Score") +
    theme_minimal() + theme(legend.position = "bottom")

  # Color by z-score
  p2 <- ggplot(umap_df, aes(x = UMAP1, y = UMAP2, color = z_score)) +
    geom_point(size = 0.8, alpha = 0.7) +
    scale_color_gradient2(low = "blue", mid = "grey90", high = "red", midpoint = 0) +
    labs(title = "Z-score", color = "Z") +
    theme_minimal() + theme(legend.position = "bottom")

  # Combine plots
  p3 + p1 + p2 + plot_layout(ncol = 3)
}

Note: Cells dominated by topics with high enrichment will appear as “hot spots” on the score UMAP. The z-score UMAP highlights cells whose scores are statistically significant after accounting for estimation uncertainty and topic correlation.

Output files

After running the pipeline, output_dir contains:

output_dir/
├── run_fastTopics_res.rds          # Step 1 results (fastTopics model + DE)
├── fasTopics_fit.rds               # Raw fastTopics model fit
├── count_mat_tp.rds                # Pseudobulk count matrix (peaks x topics)
├── beddir_list.rds                 # Step 2 results (BED directory paths)
├── cs_res.rds                      # Step 4 results (cell scores)
├── k1_output/                      # Topic 1
│   ├── k1_annotations.bed          #   BED file of topic peaks
│   ├── annotations/SIM/            #   S-LDSC annotation files
│   │   └── SIM.10.{annot.gz,l2.ldscore.gz,...}
│   ├── results/                    #   S-LDSC results
│   │   └── SIM.{results,log}
│   └── SIM_munged_sumstats.parquet #   Munged GWAS sumstats
├── k2_output/                      # Topic 2 (same structure)
│   └── ...
└── k5_output/                      # Topic 5
    └── ...

The result list returned by scads() has two elements:

  • out1: The fitted fastTopics model, including:
    • fastTopics_fit: The raw topic model object
    • Fmat: Factor loadings matrix (peaks x topics)
    • Lmat: Topic proportions matrix (cells x topics)
    • Pmat: Binary peak assignments (peaks x topics)
    • de_res: Full differential expression results (z-scores, log-fold changes)
    • baseline: The GC-content baseline used for DE testing
  • cs_res: The per-cell disease scores, including:
    • cs: Cell score vector
    • z_cell: Z-scores per cell
    • p_cell: P-values per cell
    • ldsc_res_table: S-LDSC results per topic
    • rank_fdr: Resolvable-error rank FDR of the significant cells
    • cs_dat: Intermediate M_i, N_i, the cell topic weights W and the floored-topic indicator drop
    • topic_qc: Per-topic size check and flooring decision

Troubleshooting

Common issues

Issue Solution
"sortBed" does not appear to be installed Install bedtools in your conda env: conda install -n polyfun -c bioconda bedtools
TypeError: float() argument must be a string or a real number, not 'bitarray.decodeiterator' Downgrade bitarray: pip install 'bitarray<3'
could not find function "width" Make sure GenomicRanges is loaded (scads handles this internally)
Paths with spaces break S-LDSC scads v0.2.0+ handles this via shQuote(). If using older versions, use symlinks.
S-LDSC takes too long Use chrs = 10 for testing. For production, run on a cluster with mc.cores.
